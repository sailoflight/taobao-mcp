# 项目开发 Agent 指南

> Development / Developer。只选一个子模式：`feature` 或 `initialize`。

## 子模式边界

- `feature`：新增功能、API、命令、服务、UI 行为或有意改变契约。
- `initialize`：为新或实际上为空的项目建立首套包规范。
- 修复已有行为、测试、行为保持型整理或已有项目重新适配属于 Maintainer。
- 无法判断新/已有项目或是否改变行为时，先询问再读其他角色指南。

`initialize` 只读取 `procedures/PACKAGE_ADAPTATION.md`、一个匹配 profile 和被流程点名的模板文件。该流程是初始化的唯一执行规范；不要预读下方 feature 工作流。

## Feature 任务卡

简单机械任务可跳过；其他任务先确定：

```text
结果：用户可观察行为
范围/非目标：涉及和排除的模块、契约
验收：行为、测试或输出
约束：兼容、安全、性能、网络和成本
证据：一个模块契约、实现入口、测试
验证：精确命令或人工检查
权限：生产、迁移、秘密和破坏性操作
未知：会改变行为或任务规模的决定
```

仓库证据能回答的事实自行查询；影响行为、数据、安全、兼容、成本或权限的选择集中询问一次。

## 最小上下文

```text
所选根指令文件
  -> 项目 docs/INDEX.md 的任务入口
  -> 一个相关模块契约
  -> 命中的实现和测试
  -> docs/verification/MATRIX.md
  -> 局部证据不足时才扩展架构、ADR、knowledge、evidence
```

首次不要枚举角色指南、整个仓库/文档树、生成参考、日志或完整 schema。

## 实现和验证

- 保持变更在目标模块和公共契约内。
- 遵循现有架构；只为真实复杂度或既有模式增加抽象。
- 保留用户/agent 并行修改和生成物权威来源。
- Developer 身份不授予生产、真实网络/数据、迁移、秘密、费用或破坏性权限。
- 从项目验证矩阵选择命令；风险和跨模块影响越大，覆盖越广。
- 实现/测试表示已实现行为，公共 schema 表示预期契约，架构/模块文档表示边界，roadmap 不代表当前能力。

## 文档触发

| 变化 | 更新 |
|---|---|
| 公共 API/tool/CLI 行为 | User 契约或生成参考 |
| 模块职责/依赖 | 架构、模块契约，必要时 ADR |
| 配置/部署/恢复 | Operator 文档 |
| 权限/安全/网络/成本/副作用 | 权威风险数据和受影响角色视图 |
| 已验证可复用 Bug 认知 | knowledge 并链接 evidence |
| 仅内部实现 | 通常只需测试 |
| 未实现设想 | 只进入 roadmap |

契约未变化时不要机械更新文档。

## 完成

- 满足验收并运行匹配验证。
- 公共契约和模块边界没有静默变化。
- 必要生成物和权威文档已同步。
- unknown/unverified 未伪装成事实；跳过检查和剩余风险已报告。

## 禁止

- 不得先读完整仓库或文档树。
- 不得把 User/Operator 提示放入自动根入口。
- 不得手工复制动态 tool、参数和 API 清单。
- 不得把 roadmap 当作当前行为。
- 项目路由建立后，日常任务不得每次重读本治理包。
